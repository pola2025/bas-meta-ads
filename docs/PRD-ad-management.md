# PRD: 광고 관리 기능

**문서 버전**: 1.0
**작성일**: 2025-12-10
**상태**: 구현 중

---

## 1. 개요

### 1.1 목적
대시보드에서 Meta 광고의 상태를 조회하고 on/off 제어가 가능하도록 광고 관리 기능을 추가한다.

### 1.2 범위
- **조회**: 클라이언트의 모든 광고 목록과 상태 확인
- **제어**: 광고 on/off (ACTIVE/PAUSED) 상태 변경

### 1.3 결정 사항
| 항목 | 결정 | 비고 |
|------|------|------|
| UI 위치 | 기존 대시보드에 탭 추가 | 메인 대시보드 내 "광고 관리" 탭 |
| 권한 | 클라이언트도 가능 | 해당 클라이언트의 광고만 제어 가능 |
| 표시 정보 | 기본 정보 + 성과 데이터 + 썸네일 | 광고명, 상태, 캠페인, 최근 7일 지출/리드/CPL, 썸네일 |

---

## 2. 기능 요구사항

### 2.1 광고 목록 조회

#### 표시 항목
| 필드 | 설명 | 필수 |
|------|------|------|
| 썸네일 | 광고 크리에이티브 썸네일 이미지 | O |
| 광고명 | 광고 이름 | O |
| 상태 | effective_status (ACTIVE, PAUSED 등) | O |
| 캠페인명 | 소속 캠페인 이름 | O |
| 최근 7일 지출 | 최근 7일간 총 지출액 ($) | O |
| 최근 7일 리드 | 최근 7일간 총 리드 수 | O |
| 최근 7일 CPL | 최근 7일간 평균 CPL ($) | O |
| 생성일 | 광고 생성 일시 | O |
| 제어 버튼 | on/off 토글 스위치 | O |

#### 필터/정렬
- 상태별 필터: 전체 / 활성 / 일시정지 / 기타
- 정렬: 이름순, 지출순, 리드순, CPL순, 생성일순

### 2.2 광고 상태 변경

#### 단일 변경
- 토글 스위치로 개별 광고 on/off
- ACTIVE ↔ PAUSED 상태 전환
- 변경 시 확인 다이얼로그 표시

#### 일괄 변경
- 체크박스로 여러 광고 선택
- 선택된 광고 일괄 on/off
- 처리 결과 요약 표시 (성공/실패 건수)

### 2.3 상태 값 정의

| effective_status | 한글 표시 | 색상 | 제어 가능 |
|------------------|-----------|------|-----------|
| ACTIVE | 활성 | 녹색 | O |
| PAUSED | 일시정지 | 노란색 | O |
| PENDING_REVIEW | 검토 중 | 파란색 | X |
| DISAPPROVED | 비승인 | 빨간색 | X |
| DELETED | 삭제됨 | 회색 | X |
| ARCHIVED | 보관됨 | 회색 | X |
| WITH_ISSUES | 문제 있음 | 주황색 | O |

## 3. 기술 설계

### 3.1 아키텍처

```
[대시보드 UI]
     ↓
[Next.js API Routes]
     ↓
[lib/meta.js] ← Meta Graph API
     ↓
[Supabase] ← 클라이언트 정보 (access_token)
```

### 3.2 API 엔드포인트

#### GET /api/ads
광고 목록 조회

**Request Headers:**
- `x-client-id`: 클라이언트 UUID (필수)

**Query Parameters:**
- `status`: 상태 필터 (optional)
- `sort`: 정렬 기준 (optional)
- `order`: 정렬 순서 asc/desc (optional)

**Response:**
```json
{
  "ads": [
    {
      "id": "123456789",
      "name": "20251201_리드광고",
      "status": "ACTIVE",
      "effective_status": "ACTIVE",
      "campaign_name": "12월 캠페인",
      "thumbnail_url": "https://...",
      "metrics": {
        "spend": 150.00,
        "leads": 10,
        "cpl": 15.00
      },
      "created_time": "2025-12-01T10:00:00Z"
    }
  ],
  "total": 25
}
```

#### POST /api/ads/status
광고 상태 변경

**Request Headers:**
- `x-client-id`: 클라이언트 UUID (필수)

**Request Body:**
```json
{
  "ad_ids": ["123456789", "987654321"],
  "status": "PAUSED"
}
```

**Response:**
```json
{
  "success": true,
  "results": {
    "success": ["123456789"],
    "failed": [
      { "id": "987654321", "error": "Ad is under review" }
    ]
  }
}
```

## 4. UI/UX 설계

### 4.1 탭 구조
```
대시보드
├── 개요 (기존)
├── 성과 분석 (기존)
├── 광고 관리 (신규) ← 이번 구현
└── 설정 (기존)
```

### 4.2 광고 관리 탭 레이아웃
```
┌─────────────────────────────────────────────────────────┐
│ 필터: [전체 ▼] [상태 ▼] [정렬 ▼]    [🔍 검색]          │
├─────────────────────────────────────────────────────────┤
│ ☐ 선택된 광고: 3개  [일괄 켜기] [일괄 끄기]             │
├───┬──────┬────────────┬────────┬───────┬───────┬───────┤
│ ☐ │ 썸네일 │ 광고명      │ 상태   │ 지출  │ 리드  │ 제어  │
├───┼──────┼────────────┼────────┼───────┼───────┼───────┤
│ ☐ │ [📷] │ 12월_리드1  │ 🟢활성  │ $150 │ 10   │ [ON] │
│ ☐ │ [📷] │ 12월_리드2  │ 🟡정지  │ $80  │ 5    │ [OFF]│
│ ☐ │ [📷] │ 11월_테스트 │ 🔴비승인│ $0   │ 0    │ [-]  │
└───┴──────┴────────────┴────────┴───────┴───────┴───────┘
```

### 4.3 토글 스위치 동작
1. 사용자가 토글 클릭
2. 확인 다이얼로그 표시: "광고 'xxx'를 끄시겠습니까?"
3. 확인 시 API 호출
4. 로딩 상태 표시
5. 성공/실패 토스트 메시지

## 5. 보안 고려사항

### 5.1 권한 검증
- 클라이언트는 자신의 광고만 조회/제어 가능
- client_id와 연결된 Meta 계정의 광고만 반환
- access_token은 서버에서만 복호화하여 사용

### 5.2 API 레이트 리밋 및 캐시 전략

#### Rate Limit 정보 (2025)
| Tier | 점수 한도 | 리셋 시간 | 차단 시간 |
|------|----------|----------|----------|
| Dev | 60점 | 300초(5분) | 300초 |
| Standard | 9,000점 | 300초(5분) | 60초 |

- 읽기(GET): 1점, 쓰기(POST): 3점
- 에러 코드 `#80004`: Rate Limit 초과

#### 캐시 전략 (구현 완료)
```
[데이터 흐름]
1. 캐시 확인 → 유효하면 캐시 반환 (API 호출 X)
2. Rate Limit 상태 확인 → 차단 중이면 stale cache 반환
3. Meta API 호출 → 성공 시 캐시 저장 (24시간 TTL)
4. Rate Limit 에러 → 30분 쿨다운 설정 + stale cache 반환
```

#### 관련 파일
- `lib/ad-cache.ts` - 캐시 레이어
- `migrations/add-rate-limit-column.sql` - rate_limit_until 컬럼

#### Standard Tier 승격 방법
1. Meta Developer Console에서 앱을 Live 모드로 전환
2. App Review 신청 (ads_read, ads_management)
3. 비즈니스 인증 완료
4. **1개 앱 검수 후, 모든 클라이언트가 토큰 발급하여 사용 가능**
