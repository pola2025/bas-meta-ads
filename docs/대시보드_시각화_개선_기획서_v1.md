## 1. 현황 분석

### 1.1 현재 대시보드 구성

| 영역 | 현재 구현 | 한계점 |
|------|----------|--------|
| **KPI 카드** | 4개 (리드, 지출, CPL, CTR) | 트렌드 스파크라인 없음, 목표 대비 현황 없음 |
| **트렌드 차트** | Line Chart (일별) | 단일 축, 다중 지표 비교 어려움 |
| **플랫폼 차트** | Bar Chart | 비율 표시 없음, 도넛 차트 미지원 |
| **TOP 광고** | 테이블 | 시각적 순위 표시 없음, 트렌드 미표시 |
| **광고 상세** | 정렬 테이블 | 개별 광고 히스토리 없음 |

### 1.2 데이터 저장 현황

```
현재:
├── raw_data (월별 파티션) - 일별 원본 데이터
├── daily_aggregates - 광고별 일별 집계
└── weekly_summary - 주간 요약 (리포트용)

부족한 부분:
├── 광고별 누적 데이터 없음 (전체 기간 성과)
├── 광고 성과 순위 변동 이력 없음
└── 기간별 벤치마크 데이터 없음
```

## 2. 개선 목표

### 2.1 시각화 개선 (Meta/Google 표준 참조)

> "계층적 접근 방식으로 큰 그림을 먼저 보여주고, 세부 사항으로 드릴다운할 수 있게 하라"
> — [Improvado Meta Ads Guide](https://improvado.io/blog/facebook-ads-guide)

**핵심 원칙:**
1. **정보 계층화**: 요약 → 트렌드 → 상세 순서
2. **비교 용이성**: 기간별, 광고별, 플랫폼별 비교
3. **액션 유도**: 빨간색(개선 필요) / 초록색(성과 좋음) 색상 코딩
4. **반응형**: 모바일/데스크톱 최적화

### 2.2 데이터 저장 확장

1. **광고별 누적 데이터**: 전체 기간 성과 집계
2. **일별 스냅샷**: 광고별 순위 변동 추적
3. **벤치마크**: 업종/기간별 평균값 저장

## 3. 시각화 개선 상세

### 3.1 KPI 카드 영역 개선

#### 현재
```
┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│  총 리드    │ │  총 지출    │ │  평균 CPL   │ │  평균 CTR   │
│    127건    │ │   $4,521    │ │   $35.60    │ │    2.34%    │
│   ▲ 12.5%   │ │   ▼ 8.2%   │ │   ▼ 15.3%  │ │   ▲ 0.5%   │
└─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
```

#### ✅ 확정안: 스파크라인 + 목표 대비 (A안 채택)

> **채택 이유**: 정보 밀도가 높고 공간 효율적. 게이지(B안)는 공간 대비 정보량이 낮음.

```
┌─────────────────────────────────────┐
│  총 리드                    목표 150건 │
│  ████████████████████░░░░  127건   │
│  84.7% 달성                          │
│  ▁▂▃▄▅▆▇█▇▆ (7일 추이)   ▲ 12.5%  │
└─────────────────────────────────────┘
```

**목표값 관리 방식**: `client_targets` 테이블에서 관리 (Section 4.4 참조)

## 4. 데이터 저장 확장

### 4.1 신규 테이블: ad_cumulative_stats (광고별 누적)

```sql
CREATE TABLE ad_cumulative_stats (
  id BIGSERIAL PRIMARY KEY,
  client_id UUID REFERENCES clients(id),
  ad_id VARCHAR(50) NOT NULL,
  ad_name VARCHAR(200),
  campaign_id VARCHAR(50),
  campaign_name VARCHAR(200),
  platform VARCHAR(20),

  -- 누적 지표
  total_impressions BIGINT DEFAULT 0,
  total_clicks BIGINT DEFAULT 0,
  total_leads INTEGER DEFAULT 0,
  total_spend DECIMAL(12,2) DEFAULT 0,

  -- 계산된 누적 지표
  lifetime_cpl DECIMAL(10,2) GENERATED ALWAYS AS (
    CASE WHEN total_leads > 0 THEN total_spend / total_leads ELSE NULL END
  ) STORED,
  lifetime_ctr DECIMAL(5,4) GENERATED ALWAYS AS (
    CASE WHEN total_impressions > 0 THEN (total_clicks::DECIMAL / total_impressions) * 100 ELSE NULL END
  ) STORED,
  lifetime_cvr DECIMAL(5,4) GENERATED ALWAYS AS (
    CASE WHEN total_clicks > 0 THEN (total_leads::DECIMAL / total_clicks) * 100 ELSE NULL END
  ) STORED,

  -- 메타 정보
  first_seen_date DATE,          -- 최초 데이터 날짜
  last_seen_date DATE,           -- 마지막 데이터 날짜
  active_days INTEGER DEFAULT 0, -- 실제 운영 일수

  -- 순위 정보 (일별 업데이트)
  cpl_rank INTEGER,              -- CPL 순위 (낮을수록 좋음)
  leads_rank INTEGER,            -- 리드 순위 (높을수록 좋음)

  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(client_id, ad_id)
);

-- 인덱스
CREATE INDEX idx_ad_cumulative_client ON ad_cumulative_stats(client_id);
CREATE INDEX idx_ad_cumulative_cpl ON ad_cumulative_stats(lifetime_cpl) WHERE total_leads > 0;
CREATE INDEX idx_ad_cumulative_leads ON ad_cumulative_stats(total_leads DESC);
```

### 4.2 신규 테이블: ad_daily_snapshot (일별 스냅샷)

> **파티셔닝 전략**: 초기에는 단일 테이블로 시작, 데이터가 100만 건 이상 누적되면 파티셔닝 적용

```sql
-- 초기: 단일 테이블 (파티셔닝 없이 시작)
CREATE TABLE ad_daily_snapshot (
  id BIGSERIAL PRIMARY KEY,
  client_id UUID REFERENCES clients(id),
  snapshot_date DATE NOT NULL,
  ad_id VARCHAR(50) NOT NULL,

  -- 해당 일자 기준 누적값
  cumulative_leads INTEGER,
  cumulative_spend DECIMAL(12,2),
  cumulative_cpl DECIMAL(10,2),

  -- 해당 일자 순위
  cpl_rank INTEGER,
  leads_rank INTEGER,

  -- 전일 대비 변화
  leads_change INTEGER,          -- 전일 대비 리드 증감
  cpl_change DECIMAL(10,2),      -- 전일 대비 CPL 변화
  rank_change INTEGER,           -- 전일 대비 순위 변화 (양수=상승)

  created_at TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(client_id, snapshot_date, ad_id)
);

-- 성능 인덱스
CREATE INDEX idx_snapshot_client_date ON ad_daily_snapshot(client_id, snapshot_date DESC);
CREATE INDEX idx_snapshot_ad ON ad_daily_snapshot(ad_id, snapshot_date DESC);
```

### 4.3 신규 테이블: client_targets (KPI 목표값)

```sql
CREATE TABLE client_targets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  client_id UUID REFERENCES clients(id) ON DELETE CASCADE,

  -- 월별 목표값
  target_month DATE NOT NULL,              -- 해당 월 (예: 2025-11-01)

  -- KPI 목표
  target_leads INTEGER,                    -- 목표 리드 수
  target_spend DECIMAL(10,2),              -- 예산 상한
  target_cpl DECIMAL(10,2),                -- 목표 CPL (이하)
  target_ctr DECIMAL(5,2),                 -- 목표 CTR (이상)

  -- 자동 설정 옵션
  auto_set_from_previous BOOLEAN DEFAULT true,  -- 전월 대비 자동 설정
  auto_increase_percent INTEGER DEFAULT 10,     -- 자동 증가율 (%)

  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE(client_id, target_month)
);

-- 기본 목표값 삽입 함수
CREATE OR REPLACE FUNCTION set_default_targets(p_client_id UUID, p_month DATE)
RETURNS void AS $$
DECLARE
  v_prev_leads INTEGER;
  v_prev_cpl DECIMAL;
BEGIN
  -- 전월 실적 조회
  SELECT SUM(leads),
         CASE WHEN SUM(leads) > 0 THEN SUM(spend) / SUM(leads) ELSE NULL END
  INTO v_prev_leads, v_prev_cpl
  FROM daily_aggregates
  WHERE client_id = p_client_id
    AND date >= (p_month - INTERVAL '1 month')
    AND date < p_month;

  -- 목표값 삽입 (전월 대비 10% 증가)
  INSERT INTO client_targets (client_id, target_month, target_leads, target_cpl)
  VALUES (
    p_client_id,
    p_month,
    COALESCE(v_prev_leads * 1.1, 100)::INTEGER,
    COALESCE(v_prev_cpl * 0.95, 50)  -- CPL은 5% 감소 목표
  )
  ON CONFLICT (client_id, target_month) DO NOTHING;
END;
$$ LANGUAGE plpgsql;
```

### 4.4 집계 함수

```sql
-- 일별 누적 통계 업데이트
CREATE OR REPLACE FUNCTION update_ad_cumulative_stats(p_client_id UUID)
RETURNS void AS $$
BEGIN
  INSERT INTO ad_cumulative_stats (
    client_id, ad_id, ad_name, campaign_id, campaign_name, platform,
    total_impressions, total_clicks, total_leads, total_spend,
    first_seen_date, last_seen_date, active_days
  )
  SELECT
    client_id,
    ad_id,
    MAX(ad_name),
    MAX(campaign_id),
    MAX(campaign_name),
    MAX(platform),
    SUM(impressions),
    SUM(clicks),
    SUM(leads),
    SUM(spend),
    MIN(date),
    MAX(date),
    COUNT(DISTINCT date)
  FROM daily_aggregates
  WHERE client_id = p_client_id
  GROUP BY client_id, ad_id
  ON CONFLICT (client_id, ad_id) DO UPDATE SET
    ad_name = EXCLUDED.ad_name,
    campaign_name = EXCLUDED.campaign_name,
    total_impressions = EXCLUDED.total_impressions,
    total_clicks = EXCLUDED.total_clicks,
    total_leads = EXCLUDED.total_leads,
    total_spend = EXCLUDED.total_spend,
    last_seen_date = EXCLUDED.last_seen_date,
    active_days = EXCLUDED.active_days,
    updated_at = NOW();

  -- 순위 업데이트
  WITH ranked AS (
    SELECT
      id,
      ROW_NUMBER() OVER (ORDER BY lifetime_cpl ASC NULLS LAST) as cpl_r,
      ROW_NUMBER() OVER (ORDER BY total_leads DESC) as leads_r
    FROM ad_cumulative_stats
    WHERE client_id = p_client_id AND total_leads > 0
  )
  UPDATE ad_cumulative_stats a
  SET cpl_rank = r.cpl_r, leads_rank = r.leads_r
  FROM ranked r
  WHERE a.id = r.id;
END;
$$ LANGUAGE plpgsql;

-- 일별 스냅샷 저장
CREATE OR REPLACE FUNCTION save_daily_snapshot(p_client_id UUID, p_date DATE)
RETURNS void AS $$
BEGIN
  INSERT INTO ad_daily_snapshot (
    client_id, snapshot_date, ad_id,
    cumulative_leads, cumulative_spend, cumulative_cpl,
    cpl_rank, leads_rank
  )
  SELECT
    client_id,
    p_date,
    ad_id,
    total_leads,
    total_spend,
    lifetime_cpl,
    cpl_rank,
    leads_rank
  FROM ad_cumulative_stats
  WHERE client_id = p_client_id
  ON CONFLICT (client_id, snapshot_date, ad_id) DO UPDATE SET
    cumulative_leads = EXCLUDED.cumulative_leads,
    cumulative_spend = EXCLUDED.cumulative_spend,
    cumulative_cpl = EXCLUDED.cumulative_cpl,
    cpl_rank = EXCLUDED.cpl_rank,
    leads_rank = EXCLUDED.leads_rank;

  -- 전일 대비 변화 계산
  UPDATE ad_daily_snapshot curr
  SET
    leads_change = curr.cumulative_leads - prev.cumulative_leads,
    cpl_change = curr.cumulative_cpl - prev.cumulative_cpl,
    rank_change = prev.cpl_rank - curr.cpl_rank  -- 순위 상승이면 양수
  FROM ad_daily_snapshot prev
  WHERE curr.client_id = p_client_id
    AND curr.snapshot_date = p_date
    AND prev.client_id = curr.client_id
    AND prev.ad_id = curr.ad_id
    AND prev.snapshot_date = p_date - INTERVAL '1 day';
END;
$$ LANGUAGE plpgsql;
```

### 4.5 집계 함수 실행 스케줄

> **핵심**: 데이터 수집 배치 스크립트 실행 직후 집계 함수 호출

#### 방법 1: 배치 스크립트에서 직접 호출 (권장)

```javascript
// index.js 또는 collect-data.js 수정
async function runDailyAggregation(clientId) {
  // 데이터 수집 완료 후 집계 실행
  const { error } = await supabase.rpc('update_ad_cumulative_stats', {
    p_client_id: clientId
  });

  if (!error) {
    await supabase.rpc('save_daily_snapshot', {
      p_client_id: clientId,
      p_date: new Date().toISOString().split('T')[0]
    });
  }
}
```

#### 방법 2: Supabase pg_cron (자동 스케줄)

```sql
-- pg_cron 익스텐션 활성화 (Supabase 대시보드에서)
-- Database > Extensions > pg_cron 활성화

-- 매일 자정(KST 09:00 UTC) 실행
SELECT cron.schedule(
  'daily-aggregation',
  '0 0 * * *',  -- 매일 00:00 UTC
  $$
    DO $$
    DECLARE
      v_client RECORD;
    BEGIN
      FOR v_client IN SELECT id FROM clients WHERE is_active = true LOOP
        PERFORM update_ad_cumulative_stats(v_client.id);
        PERFORM save_daily_snapshot(v_client.id, CURRENT_DATE);
      END LOOP;
    END $$;
  $$
);

-- 매월 1일 목표값 자동 설정
SELECT cron.schedule(
  'monthly-targets',
  '0 1 1 * *',  -- 매월 1일 01:00 UTC
  $$
    DO $$
    DECLARE
      v_client RECORD;
    BEGIN
      FOR v_client IN SELECT id FROM clients WHERE is_active = true LOOP
        PERFORM set_default_targets(v_client.id, DATE_TRUNC('month', CURRENT_DATE));
      END LOOP;
    END $$;
  $$
);
```

| 일별 스냅샷 저장 | 데이터 수집 직후 | 배치 스크립트 |
| 월별 목표값 설정 | 매월 1일 | pg_cron |
