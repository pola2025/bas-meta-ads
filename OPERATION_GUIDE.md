## 1. 시스템 개요

BAS Meta Ads Analytics는 다중 클라이언트의 Meta 광고 데이터를 수집하고, 자동 리포트를 발송하는 시스템입니다.

### 운영 방식

**모든 운영은 대시보드 Admin에서 수행** (CLI 미사용)

```
┌─────────────────────────────────────────────────────────────┐
│                    대시보드 Admin                            │
│                   (버튼 클릭으로 운영)                        │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    API 엔드포인트                            │
│   /api/admin/clients, /api/admin/backfill, /api/admin/status │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│                      Supabase                               │
│              (raw_data → VIEW 자동 집계)                     │
└─────────────────────────────────────────────────────────────┘
```

### 핵심 구성요소

| 구성요소 | 역할 | 위치 |
|---------|------|------|
| **Admin 대시보드** | 운영자용 관리 UI | Vercel (웹) |
| **API 엔드포인트** | 클라이언트 추가, 백필, 상태 조회 | Vercel API Routes |
| **통계 대시보드** | 클라이언트/관리자 데이터 조회 | Vercel (웹) |
| **Cron Job** | 자동 데이터 수집, 리포트 발송 | Railway |
| **Supabase** | 데이터 저장소 | 클라우드 DB |

## 3. API 엔드포인트

### 3.1 클라이언트 관리

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/admin/clients` | 클라이언트 목록 조회 |
| `POST` | `/api/admin/clients` | 클라이언트 추가 |
| `GET` | `/api/admin/clients/[id]` | 클라이언트 상세 조회 |
| `PATCH` | `/api/admin/clients/[id]` | 클라이언트 정보 수정 |
| `DELETE` | `/api/admin/clients/[id]` | 클라이언트 삭제 (비활성화) |

### 3.2 백필

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `POST` | `/api/admin/backfill` | 백필 실행 (SSE 스트림) |
| `GET` | `/api/admin/backfill/status` | 진행 중인 백필 상태 |

### 3.3 상태 조회

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/admin/status` | 시스템 전체 상태 |
| `GET` | `/api/admin/logs` | 작업 로그 조회 |

### 3.4 클라이언트 추가 API 상세

**Request:**
```json

  "account": "act_123456789",
  "token": "EAAGxxxx...",

  "autoBackfill": true,
  "backfillDays": 90
```

```json
  "success": true,
```

## 4. 백필 정책

### 4.1 월별 자동 분할

```
요청: 90일 이하  → 한 번에 실행
요청: 90일 초과  → 30일 단위로 자동 분할

예시: 365일 (1년) 요청
  ├─ 1차: 11/26 ~ 12/25 (30일) → 실행 → 로그 → 진행률 1/12
  ├─ 2차: 12/26 ~ 01/25 (30일) → 실행 → 로그 → 진행률 2/12
  ├─ ...
  └─ 12차: 10/26 ~ 11/25 (30일) → 실행 → 로그 → 진행률 12/12
```

### 4.2 실시간 로그 출력

- **기술**: Server-Sent Events (SSE)
- **갱신 주기**: 이벤트 발생 시 즉시
- **로그 타입**: info, success, warning, error, progress

### 4.3 알림 정책

| 알림 대상 | 채널 |
|----------|------|
| 백필 결과 | 관리자 채널 (`-1003394139746`) |
| 주간/월간 리포트 | 클라이언트별 `telegram_chat_id` |

## 6. 리포트 발송 일정

### 6.1 자동 발송 (Cron)

| 리포트 | 발송 시간 | Cron (UTC) |
|--------|----------|------------|
| **주간** | 매주 월요일 09:00 KST | `0 0 * * 1` |
| **월간** | 매월 1일 09:00 KST | `0 0 1 * *` |

### 6.2 발송 조건

- `is_active = true`
- `telegram_chat_id` 설정됨

### 6.3 발송 대상

- 클라이언트별 `telegram_chat_id`로 개별 발송

## 7. 로그 시스템
