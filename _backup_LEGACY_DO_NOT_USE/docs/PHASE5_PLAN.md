## 📊 Part 1: 과거 데이터 수집 (Backfill)

### 1-1. Meta API 제약 확인

**Meta Ads API 데이터 보존 기간**:
- ✅ **Insights 데이터**: 최대 **37개월** (약 3년)
- ✅ 따라서 2025년 11월 기준 → **2022년 10월**까지 조회 가능
- ✅ 9월, 10월 데이터 수집 가능!

**API 제약 사항**:
- **Rate Limit**: 200 calls/hour (Meta Graph API 기본)
- **시간 범위**: 한 번에 최대 **93일** 조회 가능
- **페이지네이션**: 데이터가 많으면 여러 번 호출 필요

---

### 1-2. Backfill 전략

#### 옵션 1: 월별 Backfill (권장)
```
9월 데이터: 2025-09-01 ~ 2025-09-30
10월 데이터: 2025-10-01 ~ 2025-10-31
```

**장점**:
- 한 번에 전체 월 데이터 수집
- weekly_summary도 자동 생성 가능

**단점**:
- 데이터가 많으면 API 호출 시간이 오래 걸림

#### 옵션 2: 주별 Backfill
```
9월:
  - 2025-09-01 ~ 2025-09-07
  - 2025-09-08 ~ 2025-09-14
  - 2025-09-15 ~ 2025-09-21
  - 2025-09-22 ~ 2025-09-28
  - 2025-09-29 ~ 2025-09-30

10월:
  - 2025-10-01 ~ 2025-10-07
  - ...
```

**장점**:
- 기존 주간 리포트 시스템과 일관성 유지
- 작업 실패 시 재시도 용이

**단점**:
- 더 많은 API 호출 필요

---

### 1-3. Backfill 스크립트 구조

**파일**: `lib/backfill.js`

```javascript
/**
 * 과거 데이터 Backfill 스크립트
 *
 * 사용법:
 * node lib/backfill.js 2025-09-01 2025-09-30
 * node lib/backfill.js 2025-10-01 2025-10-31
 */

// 1. Meta API 호출 (기존 fetchMetaAdsData 재사용)
// 2. raw_data에 저장
// 3. weekly_summary 생성 (Supabase RPC 호출)
// 4. 진행 상황 로그 출력
```

**주요 기능**:
- ✅ 날짜 범위 입력 (시작일, 종료일)
- ✅ 페이지네이션 처리
- ✅ 중복 방지 (upsert)
- ✅ 에러 처리 및 재시도
- ✅ 진행 상황 표시
- ✅ 완료 후 텔레그램 알림

## 📈 Part 2: 대시보드 시각화

### 2-1. 대시보드 목표

**핵심 질문**:
1. 어떤 광고가 가장 효과적인가? (CPL 기준)
2. CPL이 시간에 따라 어떻게 변하는가?
3. 주간/월간 성과 추이는?
4. 광고별 성과 비교는?

**사용자 요구사항**:
- ✅ **직관적 시각화**: 복잡한 데이터를 쉽게 이해
- ✅ **실시간 업데이트**: 최신 데이터 자동 반영
- ✅ **인터랙티브**: 날짜 범위, 광고 필터링
- ✅ **모바일 대응**: 스마트폰에서도 확인 가능

---

### 2-2. 대시보드 기술 스택

#### 옵션 1: Next.js + Recharts (권장)
**장점**:
- 빠른 개발 (SSR, API Routes 내장)
- Recharts (React 차트 라이브러리)
- Supabase JS SDK 직접 사용
- Vercel 무료 배포

**단점**:
- 초기 설정 필요

#### 옵션 2: Metabase (오픈소스 BI 도구)
**장점**:
- 코드 없이 대시보드 구축
- Supabase 직접 연결
- SQL 쿼리 기반

**단점**:
- 커스터마이징 제한적
- 별도 서버 필요 (Railway에 배포 가능)

#### 옵션 3: Supabase Dashboard (자체 대시보드)
**장점**:
- Supabase 내장 기능
- SQL 편집기 제공

**단점**:
- 시각화 기능 제한적
- 외부 공유 어려움

**권장**: **Next.js + Recharts** (유연성, 커스터마이징)

### 2-4. 주요 차트 종류

#### 1) CPL 추이 (Line Chart)
**목적**: 시간에 따른 CPL 변화 추이 확인
**데이터**: `weekly_summary.week_start`, `avg_cpl`
**라이브러리**: Recharts `<LineChart>`

#### 2) 광고별 성과 (Bar Chart)
**목적**: 가장 효과적인 광고 vs 개선 필요 광고
**데이터**: `weekly_summary.ad_name`, `avg_cpl` (정렬)
**라이브러리**: Recharts `<BarChart>`

#### 3) 월간 비교 (Grouped Bar Chart)
**목적**: 9월, 10월, 11월 주요 지표 비교
**데이터**: 월별 집계 (노출, 클릭, 리드)
**라이브러리**: Recharts `<BarChart>` (grouped)

#### 4) 플랫폼/디바이스 분포 (Pie Chart)
**목적**: Facebook vs Instagram, Desktop vs Mobile
**데이터**: `raw_data.platform`, `raw_data.device`
**라이브러리**: Recharts `<PieChart>`

### 2-5. 대시보드 API 설계

#### API Routes (Next.js)

**1. GET /api/kpis**
- 기간별 핵심 지표 (총 지출, 리드, CPL, CTR)
- 전기 대비 증감률

**2. GET /api/cpl-trend**
- 주간/월간 CPL 추이 데이터
- Query: `?start=2025-09-01&end=2025-11-30&granularity=weekly`

**3. GET /api/ad-performance**
- 광고별 성과 순위
- Query: `?start=2025-09-01&end=2025-11-30&sort=cpl&limit=10`

**4. GET /api/monthly-comparison**
- 월별 비교 데이터
- Query: `?months=9,10,11&year=2025`

**5. GET /api/ads/[ad_id]**
- 특정 광고 상세 데이터
